# 路线图

每个里程碑产出一个可运行的垂直切片。后续架构不在早期搭建脚手架。

## M0：基线与安全

问题：尚无稳定基线，且 `.env` 虽未跟踪但也没有被忽略。

交付物：

- 忽略 `.env` 并文档化环境配置；
- 将 `load_dotenv()` 移至 CLI 组合层；
- 将最大轮次耗尽视为显式的非成功结果；
- 将当前的单次调用行为记录为基线测试。

验收标准：

- 普通 `git add .` 不会意外包含密钥；
- 模型单元测试在无网络访问时也能运行；
- 最大轮次耗尽不能以"成功完成"的形式呈现。

## M1：结构化的模型轮次

问题：字符串无法表达工具调用或可靠的停止原因。

交付物：

- `AssistantTurn`、`ToolCall` 和结构化的消息内容；
- 更新 `ChatModel` 协议；
- 将 OpenAI 兼容的工具调用转换为领域类型；
- 使用夹具数据的适配器测试，不涉及真实 API 调用。

验收标准：

- 零个、一个和多个工具调用均能正确解析；
- 畸形 JSON 参数变为适配器错误；
- 可以区分 `length` 终止和成功停止。

## M2：工具运行时与工作区边界

问题：模型无法检查仓库，且无限制的工具不安全。

交付物：

- 工具协议和注册表；
- `read_file` 和 `search_text`；
- 规范化的工作区路径策略；
- 输出大小限制和结构化的工具错误。

验收标准：

- Agent 能回答答案存在于夹具仓库中的问题；
- `../`、绝对路径和符号链接越界被拒绝；
- 未知工具和非法参数返回错误而不导致崩溃。

## M3：真正的 Agent Loop

问题：当前继续逻辑是文本上的回调，而非基于模型/工具状态。

交付物：

- 模型 → 工具执行 → 工具结果 → 模型的循环；
- 单次 assistant 轮次中支持多个工具调用；
- 显式的 `completed`、`failed` 和 `max_turns` 结果；
- 有序的运行时事件和 JSONL 追踪。

验收标准：

- 假模型追踪覆盖两轮工具调用后完成；
- 最大轮次、取消和工具失败有互不相同的结果类型；
- 保存的追踪能解释每一次状态转换。

## M4：编辑与验证

问题：检查代码还不等于编程 Agent。

交付物：

- 确定性的 `edit_file`，要求精确匹配旧文本；
- 受控的 `run_command`，支持参数列表、超时、cwd 和输出上限；
- 文件变更和验证事件；
- 集成任务：修复夹具仓库的 bug 并通过其测试。

验收标准：

- 编辑在零个或多个匹配时失败；
- 命令超时终止子进程并返回证据；
- 路径和 cwd 不能越出工作区；
- 至少三个夹具任务通过隐藏验收测试。

## M5：证据支撑的完成判定

问题：模型的文字描述允许"假成功"的声明。

交付物：

- 包含声明的显式完成请求；
- 确定性的证据收集器；
- 包含已验证和未验证声明的最终报告；
- 对于失败或关键结果未验证的情况，CLI 返回非零退出码。

验收标准：

- 没有匹配的成功命令记录时，测试不能被报告为已验证；
- 失败的测试出现在最终报告中；
- 在任务集上测量假成功率。

## M6：评估工具

问题：没有可重复的评估，改进提案只是主观意见。

交付物：

- 夹具仓库格式和隐藏的验收命令；
- 使用独立临时副本和每任务超时的批量运行器；
- 汇总成功、假成功、轮次和工具错误的 JSON 摘要；
- 稳定的失败分类体系。

验收标准：

- 同一任务集可比较两个提示词或运行时版本；
- 至少七个任务覆盖编码、报告、安全和超时行为；
- 失败被分类以便后续分析。

## M7+：基于证据选择的改进

只有在分析 M6 的失败之后，才选择下一个特性。候选方向包括：任务账本、上下文压缩、补丁检查点、更丰富的搜索、本地模型路由，或最终引入子 Agent。它们都是待验证的假设，而非路线图的承诺。

## 下一步实现提要：M0

涉及文件：

- `.gitignore`
- `src/pi_study/model.py`
- `src/pi_study/main.py`
- `src/pi_study/agent_loop.py`
- 配置层和轮次耗尽测试

约束：

- 保持当前 OpenAI 兼容 CLI 正常运行；
- 测试不得读取 `.env` 或访问网络；
- 暂不创建目标包结构。

失败场景：

- `.env` 文件不存在；
- `max_rounds=0` 或停止条件永远不满足；
- 启动时 API 配置缺失。

当上述行为均被显式实现和测试覆盖后，M0 完成。M1 随后将字符串响应替换为第一个结构化契约。
