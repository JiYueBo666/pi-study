# 产品范围

## 产品说明

构建一个供个人在 WSL 终端使用、语言无关的 Coding Agent。它遵循 Pi 的三层结构：可复用的模型层、可复用的 Agent Loop，以及面向编码任务的产品层。

当前提供两种界面：

- 交互式、流式 CLI（`pi-study`）
- 独立 Textual TUI（`mypi`）

它暂时不是向第三方保证的稳定 SDK，也不是 IDE / Web / RPC 产品。

## 用户与环境

- 用户：单个开发者，初期即项目作者本人。
- 主机：WSL/Linux 终端。
- 工作区：启动 Agent 时的当前目录，或用户显式指定的目录。
- 仓库：任何能由标准文件操作与项目自带命令检查、修改、验证的语言与构建系统。

## 主工作流

```text
在仓库中启动 Agent（CLI 或 TUI）
  -> 描述一个编码任务
  -> Agent 检查文件和项目说明
  -> Agent 读取、搜索、修改代码
  -> Agent 在需要时运行项目命令（危险工具可要求 y/n 审批）
  -> Agent 报告结果
  -> 用户在同一交互会话继续、插话纠正、压缩上下文，或退出
  -> 对话自动保存，下次可用 --resume / /session 恢复
```

## 已实现能力

- 交互式终端输入与流式输出（CLI + TUI）；
- 从环境变量配置的一个 OpenAI 兼容模型供应商；
- 模型请求工具调用，以及模型 -> 工具 -> 模型的多轮执行；
- 编码工具：`read`、`write`、`edit`、`grep`、`find`、`ls`、`bash`；
- 相对工作区的文件操作与路径边界；
- 可见的工具活动、错误、命令输出与思考流；
- Ctrl+C 取消当前任务并返回交互提示符；
- 会话持久化：工作区 `.pi-study/sessions/*.jsonl`，自动保存 + `--resume` / `--list-sessions` / `--forget`；
- 上下文压缩：自动压缩 + `/compact`；
- 工具审批：不安全工具 ASK 模式下 y/n；
- Steering：运行中插话，下一轮注入（TUI 主入口；CLI 可观察事件）；
- UI 无关的 `/` 命令系统（CLI / TUI 共用）。

## 当前非目标

- 向第三方提供稳定 SDK 保证；
- 兼容 Pi 的 API 或会话文件格式；
- IDE 集成、Web UI、RPC 模式、print/JSON 模式；
- MCP、包管理、扩展、主题市场、子 Agent、计划模式、长期记忆；
- 会话分叉、跨会话搜索；
- 面向恶意用户的命令沙箱或安全边界；
- SQLite 等更强会话后端（当前 JSONL 足够）。

## 可用的定义

当 Agent 不需要针对语言编写特殊分支，就能在 Python、Node.js 和一种陌生语言项目中发现项目命令、修改文件并清楚地返回结果时，产品才算真正可用。

## 从 Pi 继承的设计原则

1. 核心保持小，依赖方向必须明确。
2. 模型通信、Agent 控制流、Coding 产品行为是不同关注点。
3. 优先使用文件与现有命令行工具，不先构建语言专属框架。
4. 可选界面不能成为核心依赖。
5. 只有真实工作流需要时才加入功能。
