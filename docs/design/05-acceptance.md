# 验收与测试策略

## 验收原则

每层在其公共边界测试。Coding Agent 产品要通过真实仓库工作流验收，而不只是单元测试类。自动化测试使用 mock 或录制的 Provider 流；人工冒烟测试使用配置好的真实 Provider 和一次性仓库。

## 分层验收矩阵

| 层 | 自动化验收 | 人工冒烟测试 |
|---|---|---|
| `ai` | 将录制的 OpenAI 兼容流 chunk 转为有序事件和一条完整 AssistantMessage | 用已配置 Provider 流式生成纯文本回复 |
| `ai` 工具调用 | 正确生成工具调用并拒绝畸形参数 | 模型请求已声明工具，下一次调用接受其结果 |
| `agent_core` | 模型/工具/消息循环、多调用、停止、上限、取消、错误结果、steering、输出双通道 | 真实轮次中的事件顺序仍易读 |
| `coding_agent` 工具 | Workspace 规则、精确编辑、命令结果语义、进程超时、Pydantic 参数校验 | 在一次性仓库中运行 |
| CLI / TUI | 参数/配置错误、Ctrl+C、流事件渲染、审批与共享命令 | 小项目中的交互任务 |

## 产品验收场景

### A. 只读理解

在陌生仓库中询问应用入口位置。

通过标准：

- Agent 会列出、搜索、读取仓库文件。
- 不存在 Agent 内部的语言专属代码路径。
- CLI 展示工具活动并返回输入提示符。

### B. 小型 Python 修改

要求 Agent 在一次性 Python 仓库中修复一个已知失败测试。

通过标准：

- Agent 检查代码和测试。
- 只编辑工作区内文件。
- 运行相关项目命令。
- 报告命令真实退出码和输出摘要。

### C. 小型 Node.js 修改

在一次性 Node.js 仓库中重复 B，并使用 `npm test`。

通过标准：

- 无需 Python 专属工具或代码分支。
- 工具协议和 Loop 行为保持不变。

### D. 工作区拒绝

强制文件工具访问工作区外路径，包括符号链接逃逸。

通过标准：

- 操作作为工具结果被拒绝。
- CLI 保持可用。
- 文件工具不访问外部文件。

### E. 进程失败和超时

运行一个非零退出命令和一个超过超时的命令。

通过标准：

- 两者均返回结构化命令结果。
- 已产生输出可见。
- 超时后进程组不再运行。
- Agent 可以继续或解释结果。

### F. 取消

在模型流和长命令执行期间使用 Ctrl+C。

通过标准：

- 活动轮次以 cancelled 结束。
- CLI 返回 idle 提示符。
- 已完成编辑保留在磁盘。
- idle 时第二次 Ctrl+C 退出。

### G. 工具输出与审批

让 `bash` 产生超过 12,000 字符的输出，并分别批准、拒绝一次不安全工具调用。

通过标准：

- TUI 将命令、退出码与输出分开展示；长输出默认折叠，展开后显示完整已捕获内容；
- `ToolResult.content` 只包含受限后的模型上下文文本，`ToolCompleted.display` 保留展示文本；
- 拒绝时工具不执行，模型收到配置的拒绝文案，UI 从等待审批状态恢复；
- 取消等待审批的会话不会遗留未完成 Future。

## 每阶段质量门槛

- Ruff format 和 lint 通过。
- Pyright 对公共契约和包边界通过。
- Pytest 覆盖新增行为、正常路径和一个相关失败路径。
- 单元测试不依赖真实 Provider。
- 触及 CLI、真实 Provider、文件或进程时，每阶段至少记录一条人工验证命令。

## 契约测试

以下契约测试对本架构尤其重要：

- `ai` 不导入更高项目包；
- `agent_core` 不导入 `coding_agent`；
- Provider 响应对象不逃出 `ai.providers`；
- `subprocess` 结果对象不逃出 Coding 工具；
- 每个 `ToolResult` 都引用此前的 ToolCall ID。
