# 边界与失败策略

## 工作区边界

所有面向文件的 Coding 工具都通过同一个由已解析工作区根目录创建的 `Workspace` 对象执行。

```text
read / write / edit / grep / find / ls
  -> Workspace 解析路径
  -> 工具实现操作
```

v0 规则：

- 相对路径从工作区根目录解析；
- 文件操作拒绝已解析后位于根目录外的目标；
- 绝对路径仅在其位于根目录内时允许；
- 符号链接解析不能允许逃出根目录；
- 文件缺失和非法编码变为工具结果，不能导致进程崩溃；
- 读取和搜索结果有大小/数量上限，避免挤爆上下文。

## 命令边界

Pi 暴露强大的 `bash` 工具。Python 产品也提供该能力，但必须明确：本地 shell **不是** 安全边界。命令可以访问工作区外文件、网络资源或用户凭据，只要操作系统账户允许。

v0 策略：

- CLI 事件流在命令执行前后展示每条命令；
- 命令以工作区作为工作目录启动；
- 施加可配置超时和输出上限；
- 在取消或超时时终止整个进程组；
- 向模型返回退出码、stdout、stderr、超时状态和取消状态；
- 不声称 Workspace 策略能够沙箱化 shell 命令。

真正的沙箱必须单独设计为容器、虚拟机或 OS 级策略，不能用脆弱的命令黑名单伪装。

## 编辑策略

`write` 创建或整体覆盖指定的工作区文件。`edit` 用精确的旧文本匹配进行确定性替换。

v0 中，当旧文本匹配 0 次或多于 1 次时，`edit` 必须失败。这会要求模型重新读取文件并提交无歧义编辑。

## 限制

初始默认值，可通过 Coding Agent 配置调整：

| 限制 | 默认值 |
|---|---|
| 每个用户 prompt 的 Agent 轮数 | 20 |
| 命令超时 | 120 秒 |
| 配置允许的最大命令超时 | 600 秒 |
| 发送给模型的读取/工具输出 | 100 KiB |
| 搜索匹配数 | 200 |
| 单次目录列出条目数 | 500 |

这些是可靠性限制，不是授权控制。

## 失败分类

| 失败 | 负责者 | 可见行为 |
|---|---|---|
| 配置无效 | CLI/会话启动 | 清晰错误，轮次不开始 |
| Provider 失败 | `ai` -> Agent | 当前轮次以 `model_failed` 结束 |
| Provider 工具调用畸形 | `ai` 适配器 | Provider/轮次错误，不执行歧义数据 |
| 未知工具或参数无效 | 工具运行时 | error ToolResult，Agent 可继续 |
| 文件/路径错误 | Workspace 工具 | error ToolResult，Agent 可继续 |
| 命令非零退出 | bash 工具 | 工具执行成功，但命令结果失败 |
| 命令超时/取消 | bash 工具 | 结果标记 timeout/cancel，保留已有输出 |
| Ctrl+C | CLI/会话 | 活动轮次取消，会话返回 idle |
| 不变量违反 | Agent | `internal_error`，记录诊断细节 |

## 密钥和本地数据

- `.env` 必须继续被 Git 忽略。
- 凭据只在组合边界加载。
- 命令输出和模型上下文可能包含仓库数据。
- P1 起，对话历史会自动持久化到工作区 `.pi-study/sessions/<session_id>.jsonl`：
  - 该目录已被 `.gitignore` 排除，不应提交到版本库；
  - 文件包含原始用户输入、模型回复、工具输出等本地数据；
  - 不承诺加密、自动清理或远程保留；
  - 用户可通过 `pi-study --forget <id>` 删除单个会话，或手动删除 `.pi-study/` 目录清除全部本地 transcript。
- 会话文件位于工作区内，文件工具按工作区规则可读；是否允许模型读取历史 transcript 属于产品策略，当前未做特殊隔离。
