# 开发计划

## 设计评审门槛

在本目录设计文档作为整体完成评审前，不开始产品行为代码。未解决问题必须记录在本文件或 ADR 中，不能由第一段实现代码“意外决定”。

## Phase 0：仓库准备

目标：让项目具备有意图的开发基础。

- 归档已废弃探索设计与早期字符串循环实验；
- 将包元数据与三个包对齐；
- 加入质量工具配置和本地验证命令；
- 建立设计文档索引与 ADR 约定；
- 仅保留空包目录，不实现运行时行为。

退出条件：项目布局与文档体系和本设计集一致。

## Phase 1：`ai` 文本流基线

目标：实现供应商无关的文本流与完整消息聚合。

- 定义 `ai` 消息、上下文、模型选择、流事件；
- 实现一个 OpenAI 兼容适配器；
- 提供不依赖 CLI 的真实 Provider 冒烟入口；
- 自动化测试使用录制 Provider 流。

退出条件：文本流事件准确聚合为一条完整 AssistantMessage。

## Phase 2：`ai` 工具调用协议

目标：模型请求以不包含产品专属知识的形式表达。

- 加入工具定义和工具调用内容块；
- 解析流式工具调用参数；
- 将 ToolResultMessage 序列化回 Provider 格式。

退出条件：真实模型可以请求已声明工具，并接收匹配结果。

## Phase 3：`agent_core` Loop 与事件

目标：把 Provider/工具往返提取为通用 Agent。

- 定义 Agent 工具协议、状态、结果和事件；
- 实现模型 -> 工具 -> 模型续跑；
- 实现最大轮数和取消传播；
- 保持包隔离。

退出条件：通用 Agent 可以运行多轮工具调用并输出完整事件序列，且不导入 Coding 行为。

## Phase 4：Coding Agent 核心工具

目标：让通用 Agent 在仓库中真正有用。

- 实现 Workspace；
- 实现 `read`、`write`、`edit`、`bash`；
- 执行文件工作区策略和进程限制；
- 加入 Coding 系统提示词与会话组装。

退出条件：Agent 在一次性仓库中通过验收场景 A、B、D、E。

## Phase 5：交互式 CLI

目标：能在 WSL 中日常使用。

- 交互输入循环和事件渲染；
- Ctrl+C 语义；
- 清晰的启动/配置错误；
- 仅当核心流程需要时，加入 `grep`、`find`、`ls`、`git_diff`。

退出条件：验收场景 C、F 与此前场景均通过。

## Phase 6：Pi 风格产品演进

只有在真实任务中使用 v0 后，才针对观察到的失败选择下一项能力：

| 观察 | 候选能力 |
|---|---|
| 需要持久工作 | 会话持久化与恢复（已实现，P1） |
| 长对话退化 | 上下文选择与压缩（已实现，P2） |
| 用户需要中途指令 | steering/follow-up 队列 |
| 终端输出受限 | 独立 TUI 包（进行中，`mypi`） |
| 重复定制工作流 | 扩展或 prompt template |

当前已选择并实现：

- **会话持久化与恢复**（P1）：JSONL + `agent_core/session`，含 `--resume / --list-sessions / --forget`
- **上下文选择与压缩**（P2）：`agent_core/compaction`，自动压缩 + `/compact` 手动压缩

下一步候选从剩余观察中根据真实使用选择。

Pi 有的功能不会仅因 Pi 已实现而自动纳入。

## ADR 约定

当某项决策改变包边界、公共契约、安全声明或长期依赖时，创建 `docs/adr/NNNN-title.md`。每份 ADR 包含：

```text
状态
背景
决策
后果
考虑过的替代方案
```

当前已有 ADR 0001（会话持久化）、ADR 0002（上下文压缩）和 ADR 0003（TUI 架构）；本设计文档是当前基线，后续长期取舍继续以 ADR 记录。
